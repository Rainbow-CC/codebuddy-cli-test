# Trust Survey SQL Expert

本 Skill 旨在指导 Agent 通过 SQLite 数据库 `trust_survey.db` 获取中国信托业（65家公司）的科技建设统计数据。

## 核心资源

- **数据库文件**: `trust_survey.db` （在当前skill根目录下）
- **主数据表**: `survey_data` (包含所有调研详情)
- **元数据表**: `metadata` (字段名与原始问题的映射关系)

## 辅助参考资源的使用

除了直接查询 `metadata` 表，Agent 还可以利用 `references/column_mapping.csv`：

1. **快速预览**: 在执行 SQL 前，可以读取此 CSV 文件来理解整个问卷的结构和字段分布。
2. **上下文检索**: 对于无法直接操作 SQL 的 Agent，此文件可作为 Prompt 的一部分，帮助其识别正确的字段名。
3. **备用方案**: 当数据库表结构受损或无法访问时，此文件是字段映射的唯一权威来源。

## ⚠️ 关键规则：字段命名与使用

> **`metadata` 表中的 `column_id` 就是 `survey_data` 表中的实际列名，可以直接使用。**

数据库中所有列名都采用 **`编号_描述`** 的全称格式，例如：

| metadata.column_id (= survey_data 实际列名) | 含义 |
|---|---|
| `c1_公司简称` | 公司简称 |
| `c13_2_资源投入与配置2_1_信息科技投入_不含自有科` | 2023年科技投入(万元) |
| `c14_万元_2024年` | 2024年科技投入(万元) |
| `c15_万元_2025年` | 2025年科技投入(万元) |
| `c21_2_自有科技团队总人数` | 自有科技团队总人数 |
| `c36_3_科技外包团队总人数_人` | 科技外包团队总人数 |
| `c65_是否设立了首席信息官CIO` | 是否设立了CIO |
| `c87_公司已获得以下哪些科技专项认证_证书_ISO_IE` | ISO 27001 认证情况 |

> [!CAUTION]
> **不存在** 简写的列名如 `c13`、`c36`、`c65`、`c87` 等。
> 使用简写编号查询会报错 `no such column`！
> 必须使用从 `metadata` 表获取的 **完整 `column_id`** 作为列名。

## 数据查询策略 (两步走)

为了确保查询准确，Agent 必须遵循以下流程：

### 第1步：查找目标字段的完整列名

Agent 必须先在 `metadata` 表中通过关键词搜索，获取目标字段的 **完整 `column_id`**。由于数据量不大，可以查询全量数据。

**SQL 示例:**

```sql
-- 搜索与"外包"或"投入"相关的字段
SELECT column_id, original_question 
FROM metadata 
WHERE original_question LIKE '%外包%' OR original_question LIKE '%投入%';
```

**返回结果示例:**

| column_id | original_question |
|---|---|
| `c36_3_科技外包团队总人数_人` | (1)（3）科技外包团队总人数：___人。 |

### 第2步：用完整列名查询 survey_data

将第1步获取到的 `column_id` **直接**作为 `survey_data` 表的列名使用（无需任何转换）。

**常见场景 SQL 模板:**

- **Top N 排名:**
  
  ```sql
  -- 假设第1步获取到列名为: c36_3_科技外包团队总人数_人
  SELECT c1_公司简称, "c36_3_科技外包团队总人数_人"
  FROM survey_data 
  ORDER BY "c36_3_科技外包团队总人数_人" DESC 
  LIMIT 10;
  ```

- **行业平均水平:**
  
  ```sql
  SELECT AVG("c36_3_科技外包团队总人数_人") as 行业平均值 
  FROM survey_data;
  ```

- **单个公司查询:**
  
  ```sql
  -- 查询兴业信托是否设立了CIO
  SELECT c1_公司简称, "c65_是否设立了首席信息官CIO"
  FROM survey_data 
  WHERE c1_公司简称 LIKE '%兴业%';
  ```

- **占比统计:**
  
  ```sql
  SELECT c1_公司简称, "c13_2_资源投入与配置2_1_信息科技投入_不含自有科"
  FROM survey_data 
  WHERE "c13_2_资源投入与配置2_1_信息科技投入_不含自有科" > 50;
  ```

> [!TIP]
> 由于列名包含中文和特殊字符，在 SQL 中建议用**双引号**包裹列名，如 `"c65_是否设立了首席信息官CIO"`，以避免语法错误。

## ⚠️ 数据值编码规则

数据库中的"是/否"类字段和选择题字段均使用**数字编码**，而非中文文本。

### 是否类字段（如 CIO、认证等）

| 值 | 含义 |
|---|---|
| `1` | 是 / 已设立 / 已获得 |
| `2` | 否 / 未设立 / 未获得 |

**示例：查询已设立CIO的公司**

```sql
-- ✅ 正确：用数字 1 表示"是"
SELECT c1_公司简称 FROM survey_data 
WHERE "c65_是否设立了首席信息官CIO" = 1;

-- ❌ 错误：用文字"是"查询，会返回空结果
SELECT c1_公司简称 FROM survey_data 
WHERE "c65_是否设立了首席信息官CIO" = '是';
```

### 多选/多级字段

部分字段可能有多个数字选项（如 `1, 2, 3, 4, 5`），具体含义需结合 `metadata` 表的 `original_question` 来理解。

> [!IMPORTANT]
> 当不确定某个字段的值含义时，**必须先用 `SELECT DISTINCT` 查看该字段的实际取值**，再决定如何筛选：
> ```sql
> SELECT DISTINCT "c65_是否设立了首席信息官CIO" FROM survey_data;
> ```

## 注意事项

1. **数字编码**: 是/否类字段使用 `1`=是、`2`=否，**不是文字**。不确定时先用 `SELECT DISTINCT` 检查。
2. **空值处理**: 部分公司未填写某些项，SQL 查询时注意使用 `WHERE [完整列名] IS NOT NULL`。
3. **模糊匹配**: 公司简称搜索时建议使用 `LIKE '%公司名%'`。
4. **元数据依赖**: 永远先查 `metadata` 获取完整列名，不要猜测或缩写列名。
5. **专注于用户的问题**: 仅回答用户问题，不回答数据库搜索细节。
